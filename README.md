# 📐 数学建模资料仓库

## ⚠️ 注意事项（所有人必读！！！）

1. **不要直接在 `main` 分支上修改任何文件！** `main` 分支仅由编程手统一整合后提交。
2. **每个人只在自己对应的分支上工作：**
   - 编程手 → `coding` 分支
   - 建模手 → `model` 分支
   - 论文手 → `thesis` 分支
3. **不要直接往最终版目录下放东西。** 每个人找到自己的文件夹，把资料放进自己的文件夹里。
4. **每次开始工作前，先拉取最新内容，避免冲突。**
5. **提交信息要写清楚做了什么**，不要写"更新"、"修改"这种模糊的描述。
6. **最终由编程手统一整合各分支资料，合并到 `main` 分支后提交。**

AI 会自动帮你完成克隆和分支切换。

把你的文件（模型推导、思路文档、数据文件等）放到自己的文件夹后，在 AI 对话框中输入：

> **"帮我把当前的修改提交并推送到 model 分支，提交信息写：完成了问题一的灵敏度分析模型"**

⚠️ 注意把提交信息改成你实际做的内容！

## 👨‍💻 编程手操作指南（`coding` 分支）

### 1. 切换到自己的分支

```bash
git checkout coding
```

### 2. 日常工作流程

```bash
# ① 每次开始工作前，先拉取最新内容
git pull origin coding

# ② 在自己的文件夹中编写代码、整理资料
# ...正常工作...

# ③ 查看修改了哪些文件
git status

# ④ 添加修改的文件
git add .

# ⑤ 提交修改（写清楚做了什么）
git commit -m "添加了XX模型的Python求解代码"

# ⑥ 推送到远程仓库
git push origin coding
```

### 3. 整合各分支到 `main`（仅编程手操作）

最终提交前，将各分支的内容合并到 `main`：

```bash
# ① 切换到 main 分支
git checkout main

# ② 拉取最新的 main
git pull origin main

# ③ 合并建模手的内容
git merge model

# ④ 合并论文手的内容
git merge thesis

# ⑤ 合并自己的内容
git merge coding

# ⑥ 如果有冲突，手动解决后：
git add .
git commit -m "解决合并冲突"

# ⑦ 推送最终整合版本
git push origin main
```

> 💡 **提示：** 合并时如遇冲突，Git 会标记冲突文件，打开文件手动选择保留的内容即可。

## ❓ 常见问题

### Q: push 时提示被拒绝（rejected）怎么办？

对 AI 说：**"push 被拒绝了，帮我先拉取最新内容再推送"**

或者手动执行：

```bash
git pull origin 你的分支名
git push origin 你的分支名
```

### Q: 不小心在错误的分支上修改了文件怎么办？

对 AI 说：**"我不小心在错误的分支上改了文件，帮我把修改转移到 XX 分支"**

或者手动执行：

```bash
git stash
git checkout 正确的分支名
git stash pop
```

### Q: 怎么查看自己当前在哪个分支？

对 AI 说：**"我现在在哪个分支？"**

或者手动执行：

```bash
git branch
```

带 `*` 号的就是当前分支。
